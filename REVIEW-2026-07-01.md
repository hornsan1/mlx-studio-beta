## 1. Overall verdict

The **inference core is real and mature** — this is not a facade. Text chat, the HTTP server (OpenAI/Ollama/Anthropic dialects), the CLI, MCP tool dispatch, and Whisper ASR all work end-to-end with genuine implementations, real auth, and correct streaming.

The dominant defect class is **consistency, not capability**: several UI controls write settings the runtime never reads (they look functional but do nothing), the README/docs drift from the code in both directions, and the app ships under two competing product identities. Honesty about gaps is generally good (placeholder warnings, labeled 501s) with **one notable exception: the in-app TTS UI actively misrepresents placeholder tones as real speech.**

Maturity by surface:

| Surface | Verdict |
|---|---|
| Chat + generation engine | **Real**, minus dead sampling sliders |
| HTTP server + routes | **Real / production-grade**, minor dialect bugs |
| CLI / Terminal / Tools | **Real** |
| MCP | **Real & fully dispatched** (docs say otherwise) |
| Whisper ASR | **Real** (30s cap) |
| Settings resolver | Correct precedence, but many **dead/orphan fields** |
| Downloads / HF auth / model detection | **Real & solid** |
| Image generation | **Real only via external Python `mflux`**; Swift path partial |
| TTS | **Stub** (placeholder tones) — UI dishonest |
| Branding / i18n | **Inconsistent** |

## 2. Prioritized findings

### HIGH

1. ~~**Per-chat sampling sliders are inert.**~~ **RETRACTED — false positive (verified 2026-07-01).** The audit assumed `r` in `send()` was the pure-global snapshot. It is not: `r = engine.settings.resolved(chatId:…).settings`, and the resolver **already folds chat → session → global** for temperature/top_p/top_k/min_p/repetition_penalty/max_tokens (`SettingsStore.swift:268–294`). The popover persists via `setChat(chatId,…)` under `vm.activeSessionId`, and `send()` resolves with that same `chatId` — so `r.defaultTemperature` et al. carry the slider value. Proven at runtime (chat tier surfaces and beats session) and locked with `SamplingFallbackPriorityTests.testTraceSaysChatWhenChatOverrides` / `testChatOverridesSessionPriority`. A clarifying comment was added at `ChatViewModel.swift` to prevent the same misread. **No code fix needed — sliders are live.**

2. **Per-session Cache overrides are dropped.** ✅ **FIXED (2026-07-01).** `setupCacheCoordinator` read `settings.global()` instead of the resolved per-session settings, so cache config set on an individual server session didn't take effect. Fix: threaded the four missing cache fields (`usePagedCache`, `pagedCacheBlockSize`, `memoryCachePercent`, `memoryCacheTTLMinutes`) through `LoadOptions` + `LoadOptions(from: resolved)` (`Engine.swift`, `SettingsStore.swift`) and switched `setupCacheCoordinator` to read `opts` (already built from the resolved per-session snapshot). Defaults mirror `GlobalSettings` so bare CLI construction is unchanged. Runtime-validated + locked with `LoadOptionsCacheResolutionTests`.

3. **TTS UI misrepresents placeholder output as real speech.** ✅ **FIXED & TESTED (server contract) · 🔨 UI-label build-verified (2026-07-01).** The *tested* half: a live `regression-check` boots a real `Server` and confirms `POST /v1/audio/speech` returns `X-vMLX-TTS-Backend: placeholder-tone` — the header the UI now reads. The *build-only* half: the SwiftUI help-text mapping (placeholder → honest label) compiles but wasn't rendered/executed (no UI run here). `TTSPlaybackButton` showed "Read aloud (Kokoro TTS)" / "Generating speech…" while the server returned hash-derived tone bursts. Fix: the controller now captures the `X-vMLX-TTS-Backend` response header and the help text reflects the real backend — "Play placeholder tone (neural TTS not available yet)" / "Stop (placeholder tone — not speech yet)" when placeholder, and only says "Kokoro TTS" when the server reports the real neural backend. Verified via build; UI-string logic keyed off the server's honest header. — `TTSPlaybackButton.swift`

4. **Dual product identity ships from one target.** ✅ **FIXED & TESTED (2026-07-01, per owner decision).** *Tested:* the package exposes only the `MLXStudio` app product (`swift build` links a single app), and the product name is centralized in `vMLXTheme.AppCopy.productName` — asserted `== "MLX Studio"` and *not* the runtime name "vMLX" (`regression-check`); the menu bar consumes it (compile-verified). *Residual (not executed):* the DMG bundle name + `Info.plist` display only manifest through a full-Xcode `xcodebuild archive`. Decision: **MLX Studio is the product; vMLX is the baked-in runtime/engine + CLI**, not a separate app. Changes: removed the duplicate `vMLX` app executable from `Package.swift` (now one app product, `MLXStudio`); updated `scripts/build-release.sh` + `tests/e2e/run-ui-suite.sh` to the `MLXStudio` SPM product; set user-visible name to "MLX Studio" (and copyright to © DeAlign) in `vMLX/Info.plist` + `project.yml`; converged the 5 product-name L10n entries (en/ja/ko/zh) on "MLX Studio" while keeping "vMLX runtime" labels. Signing identity (bundle id `ai.jangq.vmlx`, team, `vmlx://` scheme) intentionally kept — vMLX is the runtime and the working notarization identity. Build-verified; scripts syntax-checked; plist lint-clean. *Follow-up (owner): if DeAlign should sign under `ai.dealign.mlxstudio.beta`, switch the bundle id + team in `project.yml` — a signing/legal call left to you.*

5. **`allowedOrigins` is a dead duplicate of `corsOrigins`.** ✅ **FIXED (2026-07-01).** Removed the orphaned `GlobalSettings.allowedOrigins` field (`SettingsTypes.swift`). No consumer read it; every CORS binding site reads `corsOrigins` and passes it as the server API's `allowedOrigins:` *parameter*. `corsOrigins` is now the single source of truth, eliminating the footgun. Old persisted settings blobs decode fine (synthesized `Decodable` ignores unknown keys). Build-verified no references broke.

## 3. What's genuinely solid (don't re-litigate)

- **Streaming engine:** generation loop, cancellation (direct `cancelStream` for uninterruptible prefill), FIFO `GenerationLock`, reasoning-off content reroute, and thorough end-of-stream flushes — **no content drop** at EOS. (Refutes the isolated-parser "content vanishes" concern.)
- **Auth:** Bearer + `x-api-key` + admin token, constant-time compared, per-IP brute-force limiter, live-swappable; `/health` is the only exempt path; admin gate correctly covers `/admin/*`, cache, adapter, and `DELETE /api/delete`. No bypass found.
- **Per-session server isolation:** each session gets a real distinct `Engine`, listener, port, and SQLite-backed settings. No dead toggles (the Distributed toggle was removed, not shipped dead).
- **MCP end-to-end:** real stdio subprocess + SSE JSON-RPC handshake, `tools/list`, namespaced catalog, and **live dispatch inside the chat agentic loop** for both HTTP and CLI. Argument type-coercion is real.
- **Downloads / HF auth / capability detection / model library:** real resumable downloads, Keychain token, gated-repo flow, config-driven family detection, FSEvents-watched library. Settings resolver precedence logic is correct.
- **Whisper ASR:** genuine MLX encoder/decoder, real vDSP mel front-end, HF tokenizer, safetensors + npz fallback.
